# Codebase audit — 2026-09-06

This pass sampled the architecture, API authentication/authorization and overload middleware,
calendar scheduling, archive finalization, and their database and deployment callers. Changes
focus on reproducible correctness failures; this is not an exhaustive review of every crate.

## Fixed findings

| Area | Failure | Correction |
| --- | --- | --- |
| API-key restrictions | Child-resource guards returned early for administrators before checking the key's action ceiling. Resource listing could also return rows to a key without `view`. | Check the ceiling before administrative shortcuts and return an empty visibility set when viewing is disallowed. |
| Machine authorization | An endpoint accepting workers and agents accepted a worker key restricted to `system:agent`. | Match the principal's assigned role and that role's permitted action together. |
| Additive roles | Ranking roles from different scopes discarded permissions. A platform auditor with a team operator assignment lost audit access in that team. | Combine the actions allowed by the applicable assignments instead of selecting one ranked role. |
| RRULE cursors | The library's inclusive `after` filter returned the previous occurrence again. Range enumeration repeated that slot until reaching its cap. | Adapt the inclusive filter to the public strictly-exclusive cursor. |
| Cron precision and active windows | Cron inherited fractional seconds from the query. Looking one second before the window's true lower bound let an expired occurrence hide another active occurrence. | Normalize cron cursors to second precision and share one checked, half-open window lookup. Reject unrepresentable durations and date arithmetic. |
| Rate-limit startup | Zero, tiny positive rates, and large burst/refill combinations passed validation and could panic or overflow during quota construction. | Use one checked quota conversion for both validation and construction, including Governor's nanosecond limits. |
| Archive finalization | Dropping the final buffered writer could hide write errors before source rows were deleted. Renamed files and newly created directories were not synced. | Check gzip completion and buffered writes, sync the file before rename, and sync Unix directory entries before source deletion. |

The archive writer now has a focused module, and modified scheduling and authorization unit tests
live beside their production modules. No database schema, broker payload, provider execution path,
or runtime configuration field changed. Existing configuration defaults remain valid.

## Regression coverage

- Authorization: additive platform/local actions, matching a machine's own action ceiling,
  restrictions on six child-resource guards, and administrator/non-administrator resource lists.
- Scheduling: exact and fractional cursors, finite RRULE exhaustion, unique capped ranges,
  overlapping windows, start/end boundaries, and duration/date overflow.
- Rate limits: zero, negative zero, non-finite and tiny rates, oversized burst/refill combinations,
  and valid fractional and boundary quotas.
- Archiving: injected final-buffer write/flush failures, readable gzip output, and SQLite source
  retention followed by a successful retry after a filesystem error.

Power-loss testing has not been performed. Non-Unix directory durability and duplicate archive
records after an interrupted retry are documented in [retention guidance](../runinator-archiver/RETENTION.md).
